# SARA unified backend — production dependency manifest (CLOUD / Linux container)
#
# TARGET: Python 3.13 on Linux (python:3.13-slim). Matched to the versions
# proven working in backend/venv on this machine (Python 3.13.7).
#
# WHY 3.13 AND NOT 3.14 — this is the single change that un-broke GameForge.
# PyPI publishes no cp314 manylinux wheel for pygame 2.6.1 (or pygame-ce), so a
# Python 3.14 image cannot install it and GameForge reports "pygame is not
# installed in the backend venv". Verified present for cp313:
#   pygame-2.6.1-cp313-cp313-manylinux_2_17_x86_64.manylinux2014_x86_64.whl
#
# SCOPE — this file is the CLOUD manifest: everything that can run inside a
# Linux container. Windows desktop-control libraries (pyautogui, mss,
# uiautomation, comtypes, pycaw, pywin32, pyttsx3) are NOT here and MUST NOT
# be added — they are meaningless on Linux and they install nothing useful.
# They live in requirements-desktop-windows.txt and run on the user's PC.
#
# Every remaining heavy import in backend/app is LAZY (inside the function that
# needs it), so a missing optional package degrades one feature to an honest
# "unavailable" instead of killing the process at boot. The bare top-level
# imports are the ones that MUST be here, and they all are.

# PHASE 12 — DEPENDENCY CLASSIFICATION (why each omission is safe)
#
# Cloud-safe, deliberately NOT pinned here (all imported lazily; a missing one
# degrades a single feature to an honest "unavailable", never a boot failure):
#
#   openai-whisper==20250625        Server-side STT. ~1.5 GB with torch. Microphone
#                                   access is a LOCAL concern — it belongs to the
#                                   Windows agent, not a headless container.
#   torch==2.13.0, transformers     Server-side embeddings. ~2.5 GB. Only reached
#   sentence-transformers==6.0.0    through app/api/chat.py and documents.py, both
#                                   of which lazy-import inside the request.
#   weasyprint==69.0                Needs pango/cairo system libraries. Add with
#                                   `apt-get install libpango-1.0-0 libpangoft2-1.0-0
#                                   libharfbuzz0b libcairo2` if PDF export is wanted.
#   pytesseract==0.3.13             The pip package is a wrapper; it needs the
#                                   tesseract BINARY (`apt-get install tesseract-ocr`).
#   scipy==1.18.0, scikit-learn     Only used by heavier analytics paths.
#
# LOCAL-ONLY — Windows desktop control. CANNOT run in a Linux container by any
# configuration. These are in requirements-desktop-windows.txt, installed on the
# user's PC, and driven over the authenticated channel in
# sara_desktop/ultron_runtime.py. Putting them in this file would be theatre:
#
#   mss, pyautogui, pycaw,          screen capture, mouse/keyboard, audio mixer,
#   uiautomation, comtypes,         Win32 window/UI Automation, COM
#   pywin32, pygetwindow
#   SpeechRecognition, pyttsx3      STT via the microphone; pyttsx3 is the Windows
#                                   SAPI TTS engine and has no Linux backend.
#   playwright, opencv-python       browser control + vision, local.
#
# The honest consequence: a cloud container can PLAN and reason about desktop
# work but cannot EXECUTE it. Execution belongs to the Windows agent. That split
# is the architecture, not a workaround.
# ---------------------------------------------------------------------------
